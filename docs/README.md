# 50 / 50 — 一刀平分，恰好平衡

界面为简体中文，保留「50 / 50」名称。正式交付只有项目根目录的 `index.html`。所有样式、逻辑与图形均内联；不使用字体、图片、CDN、API 或后端。

## 运行与验收

双击 `index.html`，在现代浏览器中直接打开。点击 开始挑战；拖动鼠标或手指划线，松开后切割。线会无限延伸，但预览只突出图形内的交线。短拖动、未穿过图形、相切均不算一刀。画线中不显示面积。

验收步骤：
1. 第一回合矩形从中间横切或竖切，看到约 50.0 / 50.0、「完美平分」、加分和连击。
2. 偏离中心切割，看到真实百分比；超出容许误差扣一条生命，连击清零。
3. 暂停或打开排行榜后计时保持不变；继续或关闭排行榜后恢复。三条生命耗尽进入成绩页并记入本机榜，「再挑战一次」立即重开。「退出」记录当前成绩并返回首页，可重新开始。
4. 手机纵向划线，不触发页面滚动；刷新后保留纪录。禁用存储时仍能游戏，纪录只保留在当前会话。

键盘：聚焦画布后 ↑ ↓ 移动线、← → 旋转、回车键切割；Shift 精细调整；Esc 键暂停/恢复。后台自动暂停，回到页面后点击 「继续挑战」；揭晓阶段打开说明同样冻结过渡。

## 核心算法与系统

几何模块（`Geometry`）对直线两侧分别做半平面裁剪。以有符号叉积分类顶点，跨边界时插入线段交点。面积用鞋带公式计算，各三角裁剪片段面积相加。判定以实际面积比的误差（百分点）为准，不使用中心距离或包围盒近似。

前三级使用四边形；从第 4 回合起，偶数回合出现曲边动物，奇数回合出现面积偏置的多边形，严格交替。猫、兔采用圆脸头像，鸭、鱼采用简洁全身剪影；四种动物使用用户确认的儿童简笔画造型与显式三次贝塞尔轮廓，只保留耳朵、鸭嘴和尾巴等少量特征；只做轻微倾斜与水平镜像，让剪影容易辨认。轮廓用细分点表示，允许简单凹形；面积来自实际轮廓，曲边采用细分近似并验证不同细分密度的面积比例收敛。凹形切割可以产生多个分离片段，按三角剖分后的半平面裁剪统计两侧面积，分别渲染，避免跨凹陷把空白误画成实体。耳切算法的原理参考 [David Eberly 的三角剖分文档](https://www.geometrictools.com/Documentation/TriangulationByEarClipping.pdf)。形状仍检查边界、简单性与面积。

计算保留 1000 × 800 逻辑平面；渲染视角按当前图形包围盒与可用画布空间等比放大，指针使用同一视角的逆变换。窗口变化取消未完成手势，DPR 单独控制像素清晰度。

难度：1–3 回合容差 ±6 个百分点、12 秒；4–8 回合 ±4 个百分点、9 秒；9+ 回合 ±3 个百分点，从 7.5 秒逐渐降到 4.5 秒下限。

判定：误差（单位：个百分点）≤0.5 为完美平分；≤2 为非常精准；≤当轮容差为合格；其余为偏差过大。

计分：合格时 四舍五入［1000 ×（1 − 误差 /（容差 + 2））× 连击倍率］；失败零分。倍率 1 + min（连击次数 − 1，10）× 0.1。所有计分集中在 `Scoring.evaluate`。每个已结算回合保存最高分和最高连击。

游戏状态包括首页、游戏中、揭晓、暂停和结束；一条动画帧循环统一管理倒计时与揭晓动画。有效切割立即锁定输入、暂停计时，完美平分居中突出显示 1.8 秒，非常精准显示 1.45 秒，合格显示 1.1 秒，失败显示偏差与生命损失 1.45 秒。减少动态效果偏好下缩短过渡。连击数字随连击增加而逐渐增强缩放反馈；小字使用加深的辅助色以保证对比度。

## 本地测试

`node tests/geometry.cjs`：读取正式 HTML 内联几何与计分代码，验证已知面积、边界输入、生成图形、面积守恒、平分线、计分和语法；使用正式动物轮廓比较每段 16 点与 32 点细分，确认面积比误差小于 0.1 个百分点。

`node tests/browser.cjs`：使用本机已有的 Playwright 和 Chromium，在断网的浏览器上下文里直接打开 HTML；虚拟时钟用于完整计时状态转换。脚本默认查找当前用户已安装的辅助测试运行时，可通过 PLAYWRIGHT_NODE_MODULES 与 CHROMIUM_EXECUTABLE_PATH 指定其他已安装路径；交付 HTML 不依赖这些工具。浏览器截图写入 `outputs/browser/`。

`node tests/challenge.cjs`：直接运行正式生成器，在四个后期回合各生成 1,000 个固定种子形状，检查中心竖切、中心横切、随机角度中心切割和包围盒中心横竖切。检查面积守恒、有效形状和平分线，并与旧版基线比较；每种策略通过率不得超过 70%。权威数值见 `data/validation/challenge-metrics.json`。

完美判定时展示三簇错峰烟花：短发射轨迹、柔和光晕、逐渐下落的光点拖尾与少量星芒，采用金色、赭红和灰绿，与原界面配色一致。使用同一动画循环，不额外创建持续定时器；减少动态效果偏好下停用烟花与计时脉冲。

成绩沿用现有本地记录键，保留旧最高分/连击。自然结束与主动退出各只记录一次本局，保存分数、回合、最高连击和日期；排行榜按分数、回合、连击、时间排序展示前十，保存完整历次列表。打开排行榜暂停本局，关闭后恢复；禁用存储仍可在本次会话内使用榜单。

音效通过 Web Audio API 合成，首次交互后启动，顶部按钮可静音并保存偏好。浏览器不支持音频时仍可正常游戏。

已执行测试：12,000 个生成图形及面积守恒/平分线检查通过；离线 Chromium 桌面与移动视口的输入、计时、暂停、重试、存储降级、DPR 与布局检查通过。Chromium 的移动视口和真实 CDP 触摸事件不等同于 iOS Safari 真机测试。

## GitHub Pages 在线发布

本仓库已配置从 `main` 分支根目录发布：[在线体验](https://qiuweiliu.github.io/50-50/)。

其他仓库可将 `index.html` 放在仓库根目录并推送。进入仓库设置（Settings）→ 页面（Pages）→ 从分支部署（Deploy from a branch），选择目标分支和根目录 `/ (root)`，保存即可。无需构建步骤。推送仓库不会自动启用 GitHub Pages；在线发布需要在 Pages 设置中单独启用。

项目管理文档、测试目录和说明目录是开发辅助资料；向招聘方提交时只提交 `index.html`。
